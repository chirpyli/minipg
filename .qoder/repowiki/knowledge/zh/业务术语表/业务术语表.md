### minipg
- 定义：基于 PostgreSQL 14.23 源码裁剪而成的轻量级数据库内核学习项目，目标是将百万行级的 PG 源码删减至约十万行核心代码，仅保留数据库内核核心功能，供学习者理解 PG 内部机制。
- 别名：Mini PostgreSQL Database Management System

### Portal
- 定义：minipg 中"查询执行状态"的核心抽象数据结构（PortalData），承载一条 SQL 从创建、定义、启动到执行的完整生命周期；SQL 游标是 Portal 在用户层的具象化，而 FE/BE 协议、SPI、预编译语句等所有查询执行路径都通过 Portal 驱动执行器。
- 别名：游标底层实现、PortalData

### WITH HOLD 游标
- 定义：DECLARE CURSOR ... WITH HOLD 的跨事务游标能力：提交事务后将结果集物化到 tuplestore（holdStore）并 detoast 数据，使游标在事务结束后仍可继续读取；由 PersistHoldablePortal() 实现，并通过 PreCommit_Portals() 将 holdable 游标从当前事务中解脱。
- 别名：跨事务游标、HOLD 游标

### WHERE CURRENT OF
- 定义：基于游标定位更新/删除的 SQL 语法（WHERE CURRENT OF cursor_name），依赖 Portal 查找游标当前位置，涉及优化器强制 TID 扫描与语法 CurrentOfExpr 的支持。
- 别名：CURRENT OF

### SCROLL / NO SCROLL
- 定义：DECLARE CURSOR 的可滚动选项：未指定时系统自动判断（无行锁且执行计划支持反向扫描则启用 SCROLL）；SCROLL 强制支持全方向 FETCH（必要时插入 Materialize 节点）；NO SCROLL 仅允许向前扫描。
- 别名：可滚动游标、不可滚动游标

### pg_cursors 视图
- 定义：暴露当前会话中所有 Portal 的系统视图，由 portalmem.c 中的 pg_cursor() 函数提供数据，属于 SQL 游标层面的辅助观察工具。

### 死代码残留分析
- 定义：minipg 项目中针对已被裁剪功能遗留的惰性死代码、未清理引用、孤立语法、零调用 static 函数、未生效条件编译块等进行系统性扫描与报告的工作流程，产出写入 mydoc/DEADCODE_ANALYSIS.md。
- 别名：死代码分析、dead code analysis
