- 每个 .c 文件以标准 PostgreSQL 版权头与 IDENTIFICATION 注释开头，并在文件顶部集中 include 所需头文件。
- 计划生成采用「Path → Plan」一对一映射模式：createplan.c 中为每种 Path 子类定义独立的 `create_<type>_plan` 静态函数，再由 `create_plan_recurse` 分派调用。
- 规划过程通过回调机制解耦：`query_planner` 接受 `query_pathkeys_callback`，`planner.c` 通过 `standard_qp_callback` 注入排序/分组需求，避免紧耦合。
- 子查询与关联变量通过 PARAM_EXEC 参数桥接：父查询的 Var 引用被替换为 Param，子查询结果回填到对应 Param，由 initsplan/setrefs 统一管理生命周期。
- 全局状态集中在 PlannerInfo 节点中（如 join_rel_list、placeholder_list、fkey_list 等），各阶段函数通过读写该结构协同工作而非返回大量中间值。
