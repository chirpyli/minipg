顶层 Makefile 通过 SUBDIRS = path plan prep util 串联四个子模块，遵循 PostgreSQL 后端统一的 Makefile.global + common.mk 构建体系。
- 数据流：planner()（plan/planner.c）作为入口，先调用 prep/ 下的预处理函数对目标列、连接树、WHERE/HAVING、聚合等进行规范化；随后进入 path/ 的动态规划阶段，为每个 RelOptInfo 生成所有可行 Path（顺序扫描、索引扫描、嵌套/合并/哈希连接等），并通过 costsize.c 估计基数与代价；最后回到 plan/ 的 createplan.c 将最优 Path 转换为 Plan 树。
- 共享契约：prep/ 产出的 PlannerInfo/Query 结构被 path/ 消费以驱动 joinrels.c 的自底向上动态规划；path/ 生成的 Path/RelOptInfo/EquivalenceClass/PathKey 由 plan/ 读取并映射到 Plan 节点；util/ 提供 RestrictInfo、PlaceHolderVar、tlist、var、clauses、joininfo、predtest 等跨阶段共用的底层工具，是 prep/path/plan 共同依赖的基础库。
- 隔离机制：各子目录各自维护独立 Makefile 与 objfiles.txt，仅通过头文件暴露接口；README 明确划分了 preprocessing → path generation → plan creation 的单向流水线，禁止反向依赖。
