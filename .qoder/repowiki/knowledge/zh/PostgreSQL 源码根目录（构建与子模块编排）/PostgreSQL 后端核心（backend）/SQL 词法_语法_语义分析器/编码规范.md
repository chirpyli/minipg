- 每个 SQL 构造类别独立成 `parse_xxx.c` 文件（expr/clause/agg/func/oper/type/coerce/collate/relation/target/param/utilcmd/enr），由 analyze.c 统一调度，保持单一职责。
- 语法动作通过 `makeXxx` 静态辅助函数创建 AST 节点（如 makeStringConst、makeIntConst、makeRangeVarFromAnyName），避免在规则体内散落节点构造逻辑。
- 位置追踪统一通过 `SET_YYLLOC`/`PUSH_YYLLOC`/`POP_YYLLOC` 宏以及 `YYLLOC_DEFAULT` 宏维护，错误报告经由 `scanner_errposition` 定位到源文本偏移。
- 对外入口采用 `parse_*` / `transform*` 命名约定：`raw_parser` 负责词法+语法，`parse_analyze*`/`parse_sub_analyze` 负责语义分析，`transformTopLevelStmt`/`transformStmt` 分发具体语句转换。
- 扫描器与语法器均声明为可重入（`%option reentrant`、`%pure-parser`），所有状态保存在 `yyextra`（`core_yy_extra_type`/`base_yy_extra_type`）而非全局变量。
- 关键字表集中管理于 `src/include/parser/kwlist.h`，由 `scan.l` 的 `PG_KEYWORD` 宏展开生成 `ScanKeywordTokens[]`，并通过 `check_keywords.pl` 强制语法与关键字表一致。
