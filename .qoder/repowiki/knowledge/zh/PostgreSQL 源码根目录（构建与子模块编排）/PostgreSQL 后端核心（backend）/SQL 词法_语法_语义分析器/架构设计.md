模块按 PostgreSQL 经典三阶段组织，依赖方向严格单向：parser → nodes/rewrite/utils/catalog。
- 词法层：`scan.l`（Flex，前缀 `core_yy`）定义 token 规则与多状态机（xb/xc/xd/xh/xq/xqs/xe/xdolq/xui/xus/xeu），通过 `scanner_init`/`core_yylex` 输出 `core_YYSTYPE`；`scansup.c` 提供字符串转义等辅助。
- 语法层：`gram.y`（Bison，前缀 `base_yy`，启用 `%pure-parser`、`%locations`）消费 token 并构建原始语法树（RawStmt/SelectStmt 等），由 `parser.c` 的 `raw_parser()` 驱动，并通过 `base_yylex()` 过滤器实现一 token 前瞻以维持 LALR(1)。
- 语义分析层：`analyze.c` 的 `parse_analyze*`/`transformTopLevelStmt` 把原始语法树转为 `Query`，分派到各子文件处理特定构造：`parse_expr.c`（表达式）、`parse_clause.c`（WHERE/GROUP BY/ORDER BY 等子句）、`parse_agg.c`（聚合）、`parse_func.c`/`parse_oper.c`（函数与运算符）、`parse_relation.c`/`parse_target.c`（表与目标列）、`parse_type.c`/`parse_coerce.c`/`parse_collate.c`（类型与排序规则）、`parse_param.c`（$n 参数）、`parse_utilcmd.c`（工具命令直接包装为 CMD_UTILITY Query）、`parse_enr.c`（扩展命名关系）。
- 构建产物包含 `.o` 与生成的 `gram.c`/`gram.h`/`scan.c`，`Makefile` 通过 BISON/FLEX 标志及 `check_keywords.pl` 保证关键字表与语法同步。
