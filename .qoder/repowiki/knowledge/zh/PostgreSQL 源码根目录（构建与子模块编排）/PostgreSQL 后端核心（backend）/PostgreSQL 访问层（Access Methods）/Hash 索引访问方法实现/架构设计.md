本模块是 PostgreSQL 索引访问方法（Index AM）框架中 hash 类型的完整实现，通过 `hash.c` 中的 `hashhandler()` 构造并返回 `IndexAmRoutine`，将 `ambuild/ambuildempty/aminsert/ambulkdelete/amvacuumcleanup/amcostestimate/amvalidate/amadjustmembers/ambeginscan/amrescan/amgettuple/amgetbitmap/amendscan` 等回调绑定到具体函数。

内部按职责拆分为多个源文件：
- `hash.c`：公共入口与 Index AM 回调封装（build、insert、scan、bulk delete、vacuum cleanup）。
- `hashinsert.c`：核心插入逻辑 `_hash_doinsert`，含溢出页分配与桶分裂触发。
- `hashsearch.c`：扫描器 `_hash_first/_hash_next`，处理 split 期间新旧桶双链读取与 moved-by-split 标记跳过。
- `hashovfl.c`：溢出页与 bitmap 页的分配/回收管理。
- `hashpage.c`：元页、bucket page、overflow page 的创建、初始化与页面类型检查。
- `hashsort.c`：建索引时的 spool+sort 路径，按 bucket 号排序以减少随机 I/O。
- `hashfunc.c`：支持函数（如哈希码计算、选项解析）。
- `hashutil.c`：共享工具（如 metapage 缓存 `_hash_getcachedmetap`、桶号→物理块号映射）。
- `hashvalidate.c`：索引结构校验。
- `hash_xlog.c`：WAL 记录生成与回放（XLOG_HASH_DELETE/XLOG_HASH_UPDATE_META_PAGE/XLOG_HASH_SPLIT_CLEANUP 等）。

依赖方向自顶向下：`hash.c` 作为门面调用各子模块；所有文件共同依赖 `access/hash.h`（在父目录或上层定义）声明的 `HashMetaPageData`、`HashPageOpaqueData`、`HashScanOpaqueData` 等数据结构以及 `_hash_*` 内部 API；WAL 子系统通过 `access/hash_xlog.h` 暴露记录类型。锁粒度以 buffer content lock + pin 为主，metapage 仅在需要更新全局状态时独占锁定，遵循“先锁低编号桶”的固定顺序避免死锁。
