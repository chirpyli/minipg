- 对外暴露的 `index_*` 入口函数在内部统一通过 `RELATION_CHECKS` / `SCAN_CHECKS` / `CHECK_REL_PROCEDURE` 宏完成 Relation/Scan 有效性及 AM 钩子存在性校验后再委派给具体 AM。
- AM 钩子获取采用“先查系统目录取 handler OID，再调用 handler 返回 `IndexAmRoutine`”的两阶段模式（见 `GetIndexAmRoutineByAmId`），并在失败时根据 `noerror` 参数选择返回 NULL 或抛错。
- 扫描生命周期严格配对：AM 的 `beginscan` 必须调用 `RelationGetIndexScan` 创建 `IndexScanDesc`，而 `endscan` 仅释放 AM 自身资源，由上层 `IndexScanEnd` 负责释放 keyData/orderByKeyData 并 free scan。
- 操作符族/支持函数校验统一通过 `check_amproc_signature` / `check_amoptsproc_signature` 借助 `SearchSysCache1(PROCOID, ...)` 读取 `Form_pg_proc` 比对参数与返回值类型，并使用 `IsBinaryCoercible` 处理宽松匹配。
- 构建清单以 `OBJS = amapi.o amvalidate.o genam.o indexam.o` 显式列出目标文件，再通过 include `$(top_builddir)/src/Makefile.global` 和 `common.mk` 复用全局规则。
