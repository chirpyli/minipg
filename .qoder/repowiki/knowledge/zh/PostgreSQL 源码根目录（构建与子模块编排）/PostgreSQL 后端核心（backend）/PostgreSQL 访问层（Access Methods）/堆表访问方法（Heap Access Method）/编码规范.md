- 每个 .c 文件顶部以标准注释块声明 IDENTIFICATION 路径与文件职责，并在 INTERFACE ROUTINES 段落列出对外导出的函数集合。
- 对 Buffer 的操作遵循“先 LockBuffer(BUFFER_LOCK_EXCLUSIVE/SHARE) 再访问 Page，最后 ReleaseBuffer”的模式，且在需要跨缓冲 I/O 前先释放锁以避免死锁。
- 使用 static const 表（如 tupleLockExtraInfo）集中维护锁模式与 MultiXactStatus 之间的映射，并通过宏（LOCKMODE_from_mxstatus、LockTupleTuplock 等）进行转换与调用，避免散落的分支判断。
- 错误路径在页面写入等关键位置使用 elog(PANIC, ...) 而非返回错误码，保证数据一致性不被静默忽略。
- 通过 README.HOT 与 README.tuplock 文档化复杂协议（HOT 链、tuple 锁、MultiXact、inplace update），代码注释引用这些文档作为设计依据。
