- 对共享内存中 `PgBackendStatus` 的写统一包裹在 `PGSTAT_BEGIN_WRITE_ACTIVITY(beentry)` / `PGSTAT_END_WRITE_ACTIVITY(beentry)` 之间，并通过递增 `st_changecount` 保证读者可见一致性。
- 读取共享状态时使用 `pgstat_begin_read_activity` / `pgstat_end_read_activity` 配对，并以 `pgstat_read_activity_complete(before, after)` 判断是否需要重试拷贝。
- 所有访问共享状态的函数均以 `volatile PgBackendStatus *beentry = MyBEEntry;` 开头，并在入口检查 `!beentry` 或 `!pgstat_track_activities` 以快速返回。
- wait event 名称解析采用按类别分发的 switch 模式：外层根据高位 `classId` 路由到 `pgstat_get_wait_activity/client/ipc/timeout/io` 等静态函数，各函数内再按枚举值映射为字符串。
- 错误报告遵循 `errstart` → 一系列 `errmsg*`/`errcode*` → `errfinish` 的三段式流程，所有中间状态保存在固定大小的 `errordata[]` 栈帧中，并通过 `recursion_depth` 防止错误处理递归。
- 断言失败路径（`ExceptionalCondition`）刻意绕过 elog 体系，直接使用 `write_stderr` 输出并调用 `abort()`，以保证在严重错误场景下仍可输出诊断信息。
